# Playbook · 经营分析月报

> 唯一职责：定义经营分析月报的**执行步骤**。这是 harness 的**第一份场景剧本**（ADR-002 / ADR-032 / ADR-067），**不是产品重心，也不是唯一入口**。指标口径一律引用 `docs/20-domain/metrics.md`。登记见 `index.md`。
> 版本 v0.2 | 建立：2026-09-22 | 最后更新：2026-09-24 | 状态：**草案**（步骤已定，未实跑校准）。金额原子粒见 G-18；件数原子维见 G-17；型号维 ASP 见 M106 / ADR-047；型号维呈现键见 ADR-048；规模不按 `payment_status` / `source_name` 过滤（ADR-052 / ADR-053）；无日历不阻断规模（ADR-054）；报告期 UTC 自然月（ADR-055）；双库同一连接（ADR-056）；C1/C2 同指纹自动放行（ADR-057）；净利不纳入（ADR-058）；新站不参与同比（ADR-059）；站点/市场两粒（ADR-060 / ADR-061）；新老客 gid（ADR-062）；量价拆解 M401（ADR-063）；贡献度 M402（ADR-064）；月报 SQL 时间窗（ADR-065）；产品化分期与记忆层（ADR-066）。

## 1. 场景目标

回答四件事：这个月卖了多少、赚了多少、达成没有、为什么变。

## 2. 指标清单（按层）

| 层 | 指标编码 | 说明 |
|---|---|---|
| 规模 | M101 / M102 / M103 / M104 / M105 / M106 | GMV、净销售额、订单、件数、AOV、ASP |
| 效率 | M105 / M106 / M210 / M207a / M207b | 客单价、件单价、转化率、退货率（金额 + 件数双轨；**不出原因维**，ADR-051） |
| ~~成本利润~~ | ~~M201–M206、M208、M209~~ | ⛔ **首期不纳入设计范围**（ADR-027 / ADR-058 / R-42）：毛利、毛利率、佣金率、广告费率、履约、仓储、净利、净利率 |
| 达成 | M301 / M302 / M303 | 目标达成率、同比、环比（分子分母同为 M102 净销售额，口径一致） |
| 异动 | M401 / M402 | 量价拆解、维度归因贡献度 |
| 客户 | M501–M507 | 新老客分层（gid 与首单月均在主表内，**不额外依赖任何其他表**） |

**首期数据源（R-41，仅 8 张）**：`shopify_sales_by_order` / `refunds_lineitems` / `refunds_adjustments` / `market_goal` / `exchange_rate` / `month_basic_data` / `产品型号度数范围` / `nssku对应映射表`。
⚠ 退款两张**不是 mongo 表**：禁的是 `shopify_orders_mongo*` 系列；以 `refunds_` 开头且不含 `mongo` 的是官方 API 表（ADR-028）。

## 3. 维度树

主轴（一次扫描 30–50 个维度，每维度独立 SQL、全量留档）：

```
时间（月 / 周）
  × 站点（一店一码；`site=EU` 是独立店）
  × 市场（站点分组，按需；欧盟 = 泛欧经营区 EU/DE/FR/IT/ES/IE/UA；禁止与成员站点混加，G-22）
  × 店铺 SKU（金额原子粒，G-18）
       ├── NSSKU → 型号 → 品类/度数（件数；单型号金额）
       ├── 「套件未拆」（多型号金额，G-16）
       ├── NSSKU（仅无型号且唯一 NS 的金额降级，G-16 / ADR-039）
       └── 「未映射」（0 个 NS，或无有效型号且 ≥2 个 NS；后者须标注，ADR-046）
  × 新老客（首期仅限独立站，ADR-014 / R-15）
```

> ⚠ **首期不含渠道 / UTM 维度（ADR-024 / R-29）**。
> ADR-024 商品维写 NSSKU。现层级：店铺 SKU → NSSKU → 有效型号 → 品类（`产品类型`）/ 度电带（`度数范围`）；户储 = 度数范围「户储」标签（ADR-041～043）。金额：单有效型号跟型号走，多有效型号进「套件未拆」，无有效型号唯一 NS 降级到该 NS（G-16 / ADR-038～040）。件数两套分标注（ADR-045）：店铺 SKU = M104 / R-30；NSSKU = G-17（有型号时与型号维同一套）。型号维 ASP 只对单有效型号、且分母只用同一批行件数（ADR-047）。JOIN 键 = `产品型号`；型号维对外呈现 = `产品型号_统一`（ADR-048）。首期以主产品为核心。「配件」不是型号。
**映射**：店铺 SKU → NSSKU → 有效型号 → `产品型号度数范围.产品型号` → `产品类型` / `度数范围` / `产品型号_统一`。禁止店铺 SKU 与型号/品类/度电带同级出金额（R-51 / R-52）；禁止 JOIN 映射后对金额求和（R-50）；禁止多型号金额进成员型号（R-53）；禁止用前缀替代型号列（R-54）；禁止把「配件」当型号（R-55）；禁止用统一列当品类或 JOIN 键（R-56）；禁止另开户储列（R-57）；禁止金额 ×成员数量（R-58）；禁止两套件数混加（R-59）；无有效型号多 NS 进未映射且须按 G-21 标注（R-60）；型号 ASP 不得用套件成员件数作分母（R-61）；型号维报告不得用 `产品型号` 原文当主键（R-62）；退款连接键 `shop_name`+`name`（R-64）；未匹配退款不冲 M102（R-65）；主报告标注服从 G-21（R-66）；禁止把 `financialStatus` 当退款原因（R-67）；规模指标不按 `payment_status` 过滤（R-68）；已转正草稿计入、不按 `source_name` 过滤（R-69）；无日历不阻断规模（R-70）；报告期 UTC 自然月 × `sale_date`（R-71）；双库同一连接（R-72）；C1/C2 同指纹自动放行（R-73）；新站不参与同比（R-74）；站点 ≠ 市场（R-75）；口径可追溯（R-76）；新老客主键 gid（R-18 / ADR-062）；M401 量 = 店铺 SKU 件数（R-77）；M402 贡献度用金额切片（R-78）；月报 SQL 须时间窗、允许无 LIMIT（R-79）。

派生交叉：品类 × 站点、度数区间 × 站点、新老客 × 品类、型号 Top N（仅单有效型号金额，ADR-064）。
**互斥性要求**：归因维度必须互斥可加（R-06 / R-78）。禁止市场与成员站点混加。

## 4. 执行步骤

| 步 | 动作 | 卡点 |
|---|---|---|
| 1 | 读取 `data-sources.md` 确定接入模式，取数并生成 `source_manifest.json` | — |
| 2 | Orchestrator 生成 `plan.md`：维度树 + 指标清单 + 口径引用 + 验收标准 | **C1**：新模板/新口径必须人工审；同指纹重跑自动放行（ADR-057） |
| 3 | 按维度生成原料 SQL，全量留档。月报 SQL 必须带报告期时间窗，允许无 LIMIT（R-79）；禁止用 LIMIT 截断规模指标 | **C2**：同上 |
| 4 | 执行派生计算（groupby / 透视 / 同比环比），自动放行并留档 | — |
| 5 | Validator 断言：对账、量纲、空值率、显著性。**有日历**才先识别促销窗口再判异常（R-12）；**无日历**标 `calendar_missing`，不阻断规模（R-70） | 规模断言失败才阻断；日历缺失不整报失败 |
| 6 | Reporter 渲染 `report.md` + `charts.html` | — |
| 7 | Evaluator 按 rubric 打分；重跑一致性校验 | **C3 每次人工审核** |
| 8 | 落 `runs/<task>/` 证据包：写入 `data_completeness`（partial/final）、`report_version`、`fx_snapshot_hash`、`fx_rate_month` | — |
| 9 | **版本判定**：月内生成 = partial（汇率走回退）；次月重生成 = final（可用 N+1 汇率），产出**新版本不覆盖旧版**（G-12 / ADR-013） | — |

## 5. 报告结构（report.md）

1. 结论摘要（3–5 条，每条带支撑数字与指标编码）
2. 规模总览（GMV / 净销售额 / 订单 / 件数 + 同比环比；同比只含够龄站，新站标「新站」；可按站点或按市场，两粒不得混加）
3. 效率拆解（客单价 / 件单价 / 转化率 / 退货率）—— ⛔ **不含毛利、净利与费用结构**（首期不纳入设计范围，R-42 / ADR-058）
4. 达成情况（目标达成率，按站点；市场达成 = 成员站点加总）
5. 异动归因（Top 异动 + M401 量价 + M402 贡献度；有日历标促销窗口，无日历标 `calendar_missing`）
6. 数据说明（快照 hash、口径版本、**报告期 = UTC 自然月 / `sale_date`**、**G-21 P0 标注**；核因细节不放这里，进证据包）
