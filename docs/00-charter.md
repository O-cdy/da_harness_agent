## 1. 我们要做什么

构建面向**跨境电商行业数据分析**的 harness agent：用一层「约束 + 监控 + 评估」的外壳包住 LLM 与 SQL/Python 分析工具，使分析过程**可约束、可监控、可复现、可评估**。

一句话判据：**同一个问题问两次，数字必须一致；任何一个数字都能追到它的口径定义、SQL 和数据快照。**

## 2. 靶心场景

**经营分析月报**是 harness 的**第一份验收剧本**（ADR-002），用来压数据颗粒度与口径——**不是产品本身，也不是唯一入口**（ADR-032 / ADR-067）。产品入口并列：按剧本 `run`，以及任意数分问题 `ask`（用户行为、广告、即席 SQL 等）。无数据源的场景只许「无数据 / 口径待确认」。

维度树与月报步骤见 `docs/20-domain/playbooks/monthly-business-review.md`。全部剧本登记见 `docs/20-domain/playbooks/index.md`。

> 产品化规划见 `docs/10-architecture.md` §8–13。S0 代码待确认后开工。

## 3. 非目标（明确不做）

| 非目标 | 原因 |
|---|---|
| 实时看板 / 流式分析 | 验收场景走周期性数据快照；实时性会破坏可复现基石 |
| 自动决策与自动投放 | harness 只对分析过程负责，不做业务动作 |
| 数据采集与反爬 | 首期数据来自 MySQL 直连与本地文件导入，不含抓取链路 |
| 代替业务判断 | 结论必须落到「可行动」，但最终判断权在人 |

## 4. 验收标准

一次分析任务判定为「通过」，必须同时满足：

1. **可复现三要素齐备**：数据快照 hash + 全量代码/SQL 留档 + 参数与模型版本（缺一不出报告，见 `AGENTS.md` 守则 6）。
2. **口径可追溯**：报告中每个指标都能在 `docs/20-domain/metrics.md` 找到条目，且条目状态为「已确认」。
3. **无臆造**：数据缺失或口径未定义的指标，显式输出「无数据 / 口径待确认」，禁止估算填充。
4. **rubric 达标**：见 `docs/30-constraints/eval-rubric.md`。
5. **重跑一致**：同输入重跑，核心指标数值一致（允许 LLM 表述差异，不允许数字差异）。
