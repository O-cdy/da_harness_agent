## S0–S2 收尾 · 2026-09-25

这一阶段要收的是通用数据分析 harness 的地基，不是经营月报。2026-09-25 01:13 把 S0 到 S7 写成本地切片已落地，范围过大。S3 到 S7 仍然是骨架，没有接到运行路径。本阶段把能用测试和一次本地会话证明的 S0–S2 补上，并明确两处不能靠改文字关闭的门。

地基现在做了这些事。编排器按运行状态机走到快照，分支暂停必须带 `sha256` checkpoint。记忆只保留上期内容指纹，上期指标数字不能进本期事实。合法 SQL 先做 AST 复核；C2 仍是占位时只归档不执行。数据库登录缺失时在连接之前失败，不改走文件通道。证据轨迹是 `trace.jsonl`，只记状态、策略、审批和工件摘要。两平台合成样本带 schema 指纹、水位、未映射字段和内容 hash，输入里的邮箱和电话不会进入样本。自动化测试 128 passed、1 skipped，覆盖率 97.51%。Ruff、mypy、import-linter 通过。真实连接不在 pytest 和 CI 里。

真实库探测在本地显式跑过，证据包是 `runs/2026-09-25-zero-write-probe/`（不入库）。`source_manifest.json` 的查询 hash 是 `sha256:2f1b8c99a47dba7a0e7a53df5a7dde8ddc7ef09eeca5fa996dfefd264ffa2534`，快照 hash 是 `sha256:73ae18ae0a1057862064b88eee001b46cbdb7b5b47986f86e32881c457239a6c`。业务行读取数为 0。探测写入没有被接受，服务端错误号是 1792，会话的 `transaction_read_only` 在显式开启事务之前已经是 1。AST 也拒绝了写语句。

三层防写没有同时成立。当前登录的授权分类里包含 `ALL PRIVILEGES`，授权条数 13，所以它不是独立只读账号。会话层和 AST 层挡住了这次写入；账号层不满足 R-104。本阶段没有新建数据库用户，也没有修改授权。审批记录仍然没有 approver 和 approved_at。这两项空着是故意的：造一个只读账号或造一个批准人，都会把未完成写成已完成。
