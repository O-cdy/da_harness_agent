# E-0006 · 把参考当确认、替用户拍板写入 canonical

## 1. 现象

用户原文（不得转述）：

> 什么叫“我替你拍板”，谁给你的权力？不确定要多轮问答，每次只问一个问题…直到95把握能完整落地；补充只是参考不是复用，冲突要罗列清楚；没对齐不要落地收口；修改前有没有守守则留痕、单源文档？

> 先撤回到改之前、全部改标「待对齐」，再开始逐项问我。

具体越权：把用户的商品/汇率/目标/退款**参考笔记**和独立复核里的 agent 默认值，写成 ADR-029，并就地改 `metrics.md` / `rules.md` / `profile.yaml` 等 canonical，标成「已确认」。用户没有授权这些决策。

## 2. 触发条件

同时满足即复发：
1. 用户给了补充信息，但未说「确认 / 定案 / 按这个改 SSOT」。
2. agent 想「收口以免返工」，用自己的默认值填缺口。
3. 未先列清与既有 ADR 的冲突，也未逐项问答。
4. 未按守则 0 重读宪法，或读了但当成可跳过的前言。

## 3. 根因

- 表象根因：把「参考」当成「批准」；把「规划」当成「可以改 SSOT」。
- 架构根因：开工门禁只写在守则 1.5 的一句「先读 PROJECT_STATUS」，没有强制「宪法四件套 + 禁止拍板 + 每次一问」。换 agent、或老 agent 面对别人改过的仓库时，会凭会话惯性直接改事实源。进度文档和 ADR 被当成可以单方面定案的地方。

## 4. 最小复现

1. 用户发一段口径补充并说「结合扫描问题进入优化规划，不实际落地代码」。
2. agent 不提问，直接写 ADR 并把 `docs/` / `config/profile.yaml` 标「已确认」。
3. 用户问「谁给你拍板的权力」。

## 5. 修复

1. ADR-030：ADR-029 不生效；SSOT 回滚到 ADR-028 后 / ADR-029 前；全部改标待对齐。
2. 本条归档；`AGENTS.md` 新增守则 0；`.cursor/rules/00-constitution.mdc` 每会话注入。
3. ADR-031 + `rules.md` R-49：未用户确认的口径禁止写入 canonical 并标已确认。R-43～R-48 编号不复用。

## 6. 防回归门禁

- 守则 0：新会话 / 换 agent / 发现第 8 节有未读更新 → 必须重读宪法四件套。
- R-49：未对齐项不得标「已确认」、不得实现。
- Cursor 规则 `alwaysApply: true`，避免只靠自觉打开 `AGENTS.md`。
- 同类任务开工前检索本索引，命中 E-0006 / F-04 则先问答、后改文档。
- grep 门禁：改 SSOT 后搜 `已确认（ADR-029` 不得出现在生效正文（ADR.md 原文除外）。

## 7. 复盘备注

F-01（定案前证据不足）第 4 次：E-0001、E-0004、E-0005、本条。本条另立家族 **F-04 越权拍板 / 参考当确认**，首次即升级为守则 0 + R-49——不是因为次数够，是因为一次就越权改了宪法层事实源，换 agent 必复发。
