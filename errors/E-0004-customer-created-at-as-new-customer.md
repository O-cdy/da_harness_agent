# E-0004 · 误用 `customer_created_at`（账号注册时间）判定新客，误差 9.2 倍

| 字段 | 内容 |
|---|---|
| 编号 | E-0004 |
| 发现日期 | 2026-09-22 |
| 模块 | 客户分层口径（M501–M506） |
| 状态 | fixed |
| 关联 ADR | ADR-026 |
| 关联规则 | **R-39** |

## 1. 现象

2026-08 新客数，两种口径相差 9.2 倍，且账号注册口径**超过当月活跃客户总数**：

```
A. 客户表 customer_created_at 在本月   = 72,680
B. 销售表 MIN(sale_date) 在本月        =  7,940
参照：2026-08 有下单的 gid 数（活跃）  = 11,123
B 口径闭合验证：新客 7,940 + 老客 3,183 = 11,123 ✓
```

## 2. 触发条件

只要报告期新客用「账号注册时间落在报告期」判定即必现。
根因是注册 ≠ 首单：首单日 − 注册日分布为 0 天 178,892（41.1%）/ 1~30 天 206,167（47.4%）/
31~365 天 35,667（8.2%）/ **>365 天 14,657（3.4%）**，最长 **2,220 天**。

## 3. 根因

- 表象根因：`customer_created_at` 语义是**账号建档时间**，包含大量注册后未下单的账号。
- **架构根因**：我在核验初期写下「`customer_created_at` 可直接判定新客，比从订单表反推更可靠」——
  这是**未经实测的想当然**，把「字段名字看起来对」当成了「语义正确」。
  字段名可靠 ≠ 语义可靠；任何用于口径判定的字段都必须实测其分布。

## 4. 最小复现

```sql
-- A 口径（错误）
SELECT COUNT(DISTINCT shopify_customer_gid) FROM shopify_customers_by_site
  WHERE customer_created_at>='2026-08-01' AND customer_created_at<'2026-09-01';        -- 72680
-- B 口径（正确）
SELECT COUNT(*) FROM (SELECT shopify_customer_gid g, MIN(sale_date) f
  FROM shopify_sales_by_order WHERE shopify_customer_gid<>'' GROUP BY 1) t
  WHERE f>='2026-08-01' AND f<'2026-09-01';                                            -- 7940
```

## 5. 修复

- 新增 **R-39**：新客 = 首次下单月（`MIN(sale_date)` 落在报告期），**禁止** `customer_created_at`；
- `metrics.md` M502 / M503 更新；`data-audit.md` §12 记录实测与闭合验证；ADR-026 定案。

## 6. 防回归门禁

- **R-39（硬规则，阻断级）**。
- **门禁（流程级）**：用于口径判定的字段，必须先实测其**取值分布与时间语义**，再写进规则；
  禁止依据字段名/直觉定语义（与 E-0001 同属"未经充分实测就定案"家族）。
