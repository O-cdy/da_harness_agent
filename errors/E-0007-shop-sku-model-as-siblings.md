# E-0007 · 把店铺 SKU 与型号画成同级

> 唯一职责：记录维度树画错的根因与防回归。版本 v1.0 | 最后更新：2026-09-23 | 状态：fixed

## 1. 现象

ADR-034 写入的 playbook 维度树把「店铺 SKU」和「NSSKU」画成「型号」下的兄弟节点。用户复核：型号是 NS 维才有的属性；一个店铺 SKU 可含储能 + 太阳能板等多个 NS / 多个型号，不可能与型号同级。

## 2. 触发条件

在金额留在店铺 SKU（G-18）、对外又想按型号看金额（G-16）时，为了「不经 NSSKU 上卷金额」，把型号提升到店铺 SKU 之上或与之并列。

## 3. 根因

- 表象根因：把「金额原子粒」和「型号上卷键」画进同一棵树的同一层。
- 架构根因：型号是映射表**成员行**字段，不是 `名称` 的单值。跳过 NSSKU 赋型号，等于给套件伪造一个型号。

## 4. 最小复现

`EL300-2-07-SPFUS-00` → `Elite 300` + `Charger 2`；`AC300-7-20-SPFJP-00` → `AC300` + `PV200`。映射表 17,011 / 48,415 个名称对应 ≥2 个型号（2026-09-23 `COUNT(*)`）。

## 5. 修复

ADR-035：层级改为 店铺 SKU → NSSKU → 型号。G-16 上卷路径作废，金额进型号维待对齐。不复活 `MAX(型号)`。

## 6. 防回归门禁

R-51：型号只允许从 NSSKU 行读取。G-19 为层级 SSOT。

## 7. 复盘备注

F-01 家族（定案前把未验证的树上卷写进 canonical）。同类：E-0006。
